# Source provenance

The user-selected source is the v5 early preview deployed on 13 November 2026 at 11:09 local time. It was imported from an immutable, allowlisted local snapshot. The original source and preview installation were not edited.

Reference snapshot tree SHA-256:

`cd2fd9c2f7eec3c7347d57afbd5260a1aaf61e4637a7952999fd1ee0763f6342`

The import includes only `engine/`, `service/`, `node_pack/`, the Creative Upscaler QML components, gallery components, and the service entry point. The preview's installed QML overrides for its wrapper, tab and API client were included in the reference. No original application binary, window-frame source or internal history was imported.

`SOURCE-MAP.json` records original and public hashes for each imported path and labels additions. Per-file hashes represent the exact snapshot rather than a moving branch.

Public adaptation removes private paths, comments and historical metadata. The service gets portable configuration, process-ID ownership, an authenticated endpoint and a separate notification identity. The QML API client uses the endpoint supplied by the new host. Preferences use the standalone application's namespace. The host's frame and Settings are new.

The tests compare 184 generated Standard/Fast graph cases to SHA-256 values calculated from the immutable source snapshot, covering all five Looks, four image sizes, chained 4× stages, speed-stack states, Standard pass ordering and Fast preview modes. This is prompt identity evidence, not rendered-pixel identity evidence.

## 5.0.0-beta.1: the final v5

"The final v5" here is version 5 of Studio Artegra's in-house app (its Creative Upscaler tab), the source this standalone is made from; it is not a release of Artegra Enhancer. The Beta takes the final v5's tab, service and finish-time logic (after its four QA and fix rounds, 16 November 2026) through a three-way merge: base = the early preview above, ours = the standalone, theirs = the final v5. A frozen copy of the final v5's in-scope files had the tree hash

`3ccc1ddcfbda32a0a1dcbbe2b0eb389d14a86777f5e9ed643858f862b2e07127`

(SHA-256 over the sorted lines `path NUL sha256 LF` of 136 files under engine/, service/, node_pack/, ui/qml/ and cu_service.py). The final v5's tab had two more fix rounds after that copy was taken (17 November 2026: the Mode follows a Look, factor or fine-tuning Bolt cannot make; an Undo puts back only each image's own factor; a change made while Bolt's files are checked stays on the waiting images). `5a960d40d4c196e8f4cd4bd7acbeb4ea34c0a7e9e6c4a05e8a05602f01ea7cfc`

(the same 136 files and method). No engine, node pack or service file changed in those rounds.

`SOURCE-MAP.json` records, per file, the final v5's SHA-256 and this release's. The Beta's own changes (the Redux and Bolt names and marks, the two-card Bolt rule, the update check, the uninstaller, the About page and the name) are listed in CHANGELOG.md, with the hardening round's small fixes from a UI/UX audit (modal Settings and About, honest start-up and engine-stopped states, the Save GPU memory retry, track contrast, preferences kept per state folder, the stale close prompt, the Shortcuts list, Windows reduced motion). `tests/test_service_prompt_identity.py` checks that the prompts the service sends for every Look, scale and mode equal the final v5's.

## 5.0.2 (in development): the Large-image engine and the SAM step that fits the card

5.0.2 is built on 5.0.1 as published. Its new code was written for Artegra Enhancer; nothing in it is imported from the final v5 or from another product. Where a new file follows third-party code step for step, the line below names it. The private merge verification described above covers the files as 5.0.0-beta.1 released them and does not cover 5.0.2's changes. Their checks are the 5.0.2 identity harness instead: `tests/test_engine_identity.py` (G0a-G0c: every plan 5.0.1 makes keeps its plan, its graph hashes and its classic engine and node-pack files), the registered hunk of `Runner._run_stage` (`tests/fixtures/run_stage_5_0_2.diff`), the registered fork of the classic spot node (`tests/fixtures/spot_banded_5_0_2.diff`), the registered lean-SAM exception (`tests/fixtures/sam_lean_5_0_2.*`), the two node-pack manifests, and the code pin (`tests/fixtures/beta-normalised-hashes.json`), which is regenerated when a build wave is merged. In `SOURCE-MAP.json`, the layers `5.0.1` and `5.0.2` mark the files changed after 5.0.0-beta.1 (`tests/test_source_map.py` checks that every file is listed and that a file without a later layer is still as 5.0.0-beta.1 released it). A file new after 5.0.0-beta.1 has no recorded hashes until the release that ships it records them.

The engine's base (written for 5.0.2):
- `engine/planner.py` keeps 5.0.1's planner verbatim as `plan_501` and adds a router. The Large-image engine is asked only for plans 5.0.1 refuses, and it admits none until the GPU proof sets `engine/banded_plan.BANDED_PROVEN_MP`.
- `engine/banded_plan.py` is the Large-image planner and its memory model.
- `engine/graph_banded.py` builds the Large-image prompts with the classic stage's input values.
- `engine/planes.py`, `engine/bands.py`, `engine/dat_bands.py` and `engine/lanczos_bands.py` are the plane store, the band arithmetic, the classic margin tiling in row bands (the same sums in the same order) and Pillow's two Lanczos passes in bands.
- `service/plane_io.py` holds the streamed writers, the viewer proxy and the regions. `service/banded_runner.py` runs the Large-image stages, and `service/build_channel.py` is the developer-build switch.
- `node_pack/claude_banded/` is the second node pack, with its own GPL-3.0 licence copy and its own manifest `node_pack/MANIFEST-banded.json`. The classic pack is untouched apart from the lean-SAM exception.
- Smaller changes are in `service/api.py`, `config.py`, `fake_comfy.py`, `media.py`, `runner.py` (the registered hunk) and `util.py`.

The SAM step that fits the card, and honest times:
- `node_pack/claude_creative/sam_lean.py` is a node with SAM3_Detect's inputs and outputs. It thresholds the masks first and upsamples only the kept ones, and it calls the runtime ComfyUI's own SAM3_Detect helpers.
- Its registration in `node_pack/claude_creative/__init__.py` and `node_pack/MANIFEST.json` is the registered exception.
- `engine/planner.py` and `engine/graph_v5t.py` carry the SAM ceiling and the fitted stage times. `service/engine_options.py`, `mask_graph.py`, `workers.py`, `comfy.py` and `runner.py` follow them.

Build wave 1:
- `node_pack/claude_banded/spot_banded.py` is a fork of `node_pack/claude_creative/spot.py` (unchanged) by the registered patch `tests/fixtures/spot_banded_5_0_2.diff`. The ControlNet hint reaches each window from its plane, a coverage mark is checked, the two-card split is static, the Brownian cache is an input, and torch is imported on first use.
- `node_pack/claude_banded/vae_planes.py`: CUEncodePlane runs the lines of ComfyUI's `VAE.encode_tiled_` (three tilings, ComfyUI's own `comfy.utils.tiled_scale`) on canvas windows read from the plane. CUDecodePlane follows `VAE.decode_tiled_` and `comfy.utils.tiled_scale_multidim` (tile positions, feather masks, add order) in row buffers, then ImageScale area and the finish's 8-bit step (ComfyUI at the runtime's commit, GPL-3.0).
- `node_pack/claude_banded/cn_plane.py` holds PlaneHint and CUControlNetApplyPlane, which calls ComfyUI's own `ControlNetApplyAdvanced.apply_controlnet` with the hint plane.
- `node_pack/claude_banded/canny_plane.py` runs ClaudeCannyTiled's tiles (kornia canny, hysteresis off) and its `scipy.ndimage.label` hysteresis, on planes.
- `node_pack/claude_banded/sam_plane.py` runs the classic pack's lean SAM node on a float32 view of the input plane.
- `node_pack/claude_banded/noise_banded.py` is the Brownian cache cap: a subclass of ComfyUI's BrownianTreeNoiseSampler in the classic noise prefetch's class-factory pattern (`claude_creative/noise.py`).
- `engine/bxf/` is new: the banded exact finish's numeric machinery.
  - Exact streamed selection on numpy's own percentile and median arithmetic (`selection.py`).
  - scipy's uniform_filter as whole-line strip and band passes (`uniform.py`).
  - The finish's 288-aligned pooled grids and whole-call zooms into mapped outputs (`pooling.py`).
  - Label, bincount, find_objects and keep tables on mapped planes (`components.py`).
  - The band executor (`local.py`), a CPU process pool for numpy and scipy band ops (`pool.py`, `_child.py`, `ops.py`) and mapped scratch planes (`work.py`).
  - The G1 classification table and its reader (`g1.py`, `g1_table.py`, written by `tools/gate_g1.py`). Each banded op carries the band geometry it was measured exact on, and the reader bands a pass only inside it.
  - It calls numpy and scipy only, and torch inside functions.
- `engine/bands.py` gains the registered finish band budgets (2, 3 and 6 GiB), their check, and the defaults (2 GiB, 1 process).
- `node_pack/claude_banded/bxf/` is CUFinishBanded with its fallback ladder, plus `finish.py`, the banded passes of 5.0.1's finish over planes.
  - Tier 0 is the banded exact finish where the G1 table applies. Tier 3 is 5.0.1's own v4_finish and shadow toe run whole, up to the size limit; its body is the earlier build's node, pinned in `tests/fixtures/finish_banded_5_0_2_base.txt`.
  - The passes call the classic `node_pack/claude_creative/v4finish.py` functions (read, never patched) and mirror v4_finish's own expressions line by line.
- `engine/vram_model.py` (the classic graphics-memory pre-check, the Large-image memory classes and the card class table) and `service/card_factor.py` (per-card time factors for deadlines, stall limits and the times said) are new. The card class table holds the makers' published figures (SM counts and memory bandwidths) as estimates, doubled for safety and replaced by the card's own measurement after its first image. The reference time per window (0.147 s) is the median of 339 sampling passes of the product stack on one RTX 5090.

Build wave 2:
- `engine/banded_plan.py`: the finish tier is a plan constant. Where no G1 table applies to the computer's processor (since build wave 3 the table decides, below; `BXF_AVAILABLE` is a test setting, off in this build), every Large-image plan counts 5.0.1's whole finish: the larger of 5.0.1's measured peak model for the stage and the whole finish's measured commit. Such a plan is refused, naming the size, above the banded pack's `FINISH_WHOLE_MAX_MP` or over the memory cap. The finish's band budget and process count per machine class are plan constants. Banded Bolt is planned (2x at supersample 2, a render of up to 150 MP, the LoRA weight backup counted at its measured 7.2 GiB) and records the installed Fast recipe's name and version. The Brownian cache is capped at 8 for Redux after its gate passed on the worker runtime; Bolt keeps 45 until its own schedules pass. New memory terms count lf.dm on narrow stages, the RGBA viewer copies and CUCannyPlane's working set; new time terms count the spot fork's host crop uploads, the lean SAM's float32 views and the plane band I/O. An image more than 100 times taller than wide is refused.
- `engine/graph_banded.py`: the finish node takes band_gb, processes and finish_tier from the plan constants (a plan without them passes none, so earlier graphs are unchanged), and `bolt_patch` is a copy of `engine/fast_recipe.py`'s Fast patch values, checked against that file's source by a test.
- `service/engine_options.py`: a Large-image Bolt plan is admitted only when banded Bolt is proven, or for a forced plan in a developer build.
- `engine/bxf/g1_table.py` holds one G1 classification table per environment: this workstation on torch 2.9.1 and on the worker runtime, and the render-node class on the worker runtime (both nodes' tables, merged into one environment). `TABLE` stays the first, for readers of one table. It holds sizes and classifications only; the processor string is its only machine fact. `engine/bxf/g1.py` applies the table whose environment matches exactly, and a local table alone or as a veto, and reads whole everywhere else.
- `engine/bxf/selfprobe.py` (new) is the start-up self-probe on the person's processor: every op G1 classes, band against whole, at 8,192 px and at each finish stage width of the plan, at the band heights the band executor picks at the given band budgets, skipping none. It writes a local table in the same format and runs by path; numpy, scipy and torch are imported inside its functions. Build wave 3 wires it into the app (below).
- `engine/bxf/memory.py` (new, pure Python) is an upper bound of the finish's own commit for each tier. It counts every pass, whole-plane step and stage output that the worker's G1 table leaves whole at the stage, and any band over its budget, and is fitted as an upper bound of fresh-process measurements on torch 2.9.1 and on the worker runtime (`tests/fixtures/bxf_finish_memory.json`).
- `engine/bxf/local.py`, `pool.py`, `_child.py` and `selection.py`: the band executor routes the registered pool steps into the process pool where G1 measured them and records band overruns; the pool's child processes run isolated with the parent's package folders; the exact selection checks numpy's helpers before the finish starts.
- `node_pack/claude_banded/bxf/`: CUFinishBanded takes band_gb, processes and finish_tier, refuses any other value in plain words, runs only the tier the plan counted, and records its tier, band budget, process count, whole and pooled passes and band overruns (in its log line, its UI planes and the output plane's header).
- `service/workers.py`: every engine loads both of the app's node packs, claude_creative and claude_banded. The engine's start check is the classic one, unchanged, so a Large-image pack that fails to load never stops a Classic engine image. Each start records the Large-image classes the engine lacks and checks the inputs the Large-image graphs send, in the log only.
- `node_pack/claude_banded/cn_plane.py`: the tile ControlNet hint reaches the ControlNet in the Classic engine's memory format, read at run time from ComfyUI's own ImageBlur, ImageScale and common_upscale.
- `node_pack/claude_banded/sam_plane.py`: the lean SAM node writes its float32 view of the stage input once per stage, and every SAM term of the prompt reuses it (the same masks). `node_pack/claude_banded/canny_plane.py`: its note gives the node's private working set per render column.
- The service (written for 5.0.2, no imported code):
  - `service/runner.py`, outside the registered hunk: a Large-image result's viewer copies are made again from its planes after a restart; the physical-memory admission of a Large-image image's work files; the forced developer plan in the job's run mode; the start-up timing of a new graphics card of 24 GiB or less by its own small prompt; the protected-area preview's time limit at the card's factor; and refusals that name the size they refuse.
  - `service/banded_runner.py`: the check for the Large-image engine's parts before every Large-image prompt; the plane count of each phase from the plane contract; the match of a saved first part without the live-preview input and the finish values that change no pixel; a Bolt stage's recipe record and each finished stage's finish tier.
  - `service/card_factor.py`: the start-up measurement prompt, on a synthetic picture. `service/comfy.py`: progress weights of CUUpscaleCanvas and CUBlurPlane. `service/fake_comfy.py`: one more test-only fault.
  - The physical-memory rule counts each Large-image image at its worst phase (its commit and the planes that phase touches, from the plane contract and `engine/banded_plan.py`'s stage sizes), beside 5.0.1's own physical check, which it never loosens. It is a registered rule until the GPU proof measures it.
- Developer tools that are never shipped:
  - `tools/gate_g1.py`, `gate_g1x.py` and `gate_g2.py`: G1 in shards, on the registered targets' own stage shapes and with the pool steps at production widths up to 32,000 px, with one table writer per environment; G1x against numpy's own percentile and median; G2 at stage factor 1.5 and on a 6x plan's last stage, with a narrow scene that holds every branch, a process count and table files.

Build wave 3:
- `engine/banded_plan.py`, the start-up probe's planner half: the G1 table that applies to the computer's processor decides the finish tier (`BXF_TABLE`, which the service sets from the engine runtime's own environment; `BXF_AVAILABLE` keeps its meaning for tests only). A banded finish planned with a table counts the finish's own commit bound with that table and records which passes the table runs whole; the plan constant `bxf_table` names the table and changes no pixel. `probe_widths` gives the probe its widths, planned with the best case any table gives, so it names none where no table could admit the image.
- `engine/banded_plan.py`, the refit to upper bounds of what is measured: tier 3 counts the largest of three bounds; every phase counts the engine's retained commit; a pass after a finish counts what that finish left in the engine only where that was measured for every setting the finish may run with. In 5.0.2 that is nowhere (it was measured without protect and release masks, which the planner cannot see), so every pass after the first starts in a fresh engine, and its minutes count the restart. lf.dm's narrow width comes from the worker runtime's tables, and admission compares the unrounded bound. The planner's refusals name the Large-image engine and the size.
- Banded Bolt: the planner makes Bolt only with the recipe the Large-image graph copies, Bolt's minutes are its own, and Bolt caps the Brownian cache at 8 after its gate passed on its own schedules (`tools/gate_g7.py --schedules bolt` and `redux-looks`).
- `engine/bxf/memory.py`: `MARGIN_WAVE3` and `RAISED`. The banded exact finish's commit bound was measured at the production band budgets and process counts (3 GiB with 2 processes, 6 GiB with 4, and 2 GiB with 1), with protect and release masks on, on the release bar's finish planes from 30.6 to 490 MP and once with every op whole, and tier 3 at 32,000 px wide stages (every branch at 1,200 and 2,400 rows; at 600 and 320 rows the scene holds only some of them). Every measurement is under the bound by at least the stated margin, so no coefficient changed.
- The finish's work disk: `engine/bxf/memory.py`'s `SCRATCH_BPO` and `STAGE_PLANES_BPO`, measured on the release bar's finish planes (the scratch folder peaked at 297.5 B per finish-plane pixel in every run). The planner's disk figure and the service's disk check count 310 B per finish-plane pixel over the stage's padded finish plane (`banded_plan.DISK_O`; `engine/planes.live_bytes`, 170 I + 25 R + 310 O, to which `disk_need` adds a tenth). The physical-memory rule's finish phase counts the 130 B the finish still touches: the stage's own planes and the finish's live scratch (`service/banded_runner.FINISH_LIVE_BPO`, 118 B; the finish's workspace counted 116.0 at its peak). The rest of the folder is scratch the finish has freed, file-backed and never read again, which costs disk only.
- `engine/bxf/selfprobe.py`: the probe's memory-cap check counts the probe process's own commit (`PROCESS_GIB`, from measured runs), so a refusal is honest at every width; the table records the figure it compared.
- `service/bxf_probe.py` (new), the start-up probe's service half: it reads the engine runtime's environment (`engine/bxf/g1.environment`, run by the runtime's interpreter and cached in the state folder), sets the G1 table the planner counts before any Large-image plan, and runs `engine/bxf/selfprobe.py` only where no committed table applies: alone, below normal priority, inside the engines' Job, stopped at its deadline, its table moved into place only when it completes. The environment read holds its own lock, so the dispatcher never waits for it; a read that failed at start is tried once more before a plan that counted the table is failed.
- `service/runner.py`, outside the registered hunk: only a plan the table can change waits for it, for less than the app's own time limits, and never under the runner's lock (a plan 5.0.1 makes and the plan cards never wait). Queued Large-image images are planned again at every start, after recovery, and when the table changes (the same pixels, their work kept). The probe never runs beside an image, every queued image says so with its remaining time, and its commit is counted; a probe that failed is not run again at that band budget in the same session, and only a refusal the probe can lift asks for it. The developer-only `dev_keep_planes` job field (a release build refuses it). The Large-image sidecar gains the processor, the table and each stage's whole passes.
- `service/banded_runner.py`: a fresh engine before a pass whose plan asks for one, or whose engine was started with another local table; the plan's table name left out of the saved first part's match; the finish record's whole passes checked against the plan's (a warning in the log); kept planes and stage files in developer builds; a plan whose table no longer applies is refused before its pass.
- `service/workers.py`: every engine start carries `CU_BXF_LOCAL_TABLE`; the Large-image class list is read before the input check, which alone is guarded; the Large-image input check covers the Bolt graph.
- Docs: `docs/STRINGS.md` lists the reasons a saved first part can be refused, read from the source both ways by `tests/test_views_strings.py`. The release drafts say that the first Large-image image on a computer waits while the app measures its processor, unless that kind of processor was measured before the release, and that a Large-image upscale restarts the image engine between passes, with each restart in the estimated time. The known issues keep a placeholder for the graphics cards the proof record names.
- Developer tools that are never shipped:
  - `tools/gate_g2.py`: its measuring children run at the run's process count; one finish can be measured alone in its own Job object (the output's data hash, the workspace's bytes, the scratch folder's real size, a volume floor), and the branches a scene exercises are named.
  - `tools/proof/` and `tests/proof/`: every harness prompt is sent under a canonical UUID prompt id, and the worker's own folders are made; a Bolt pair's forced plan is made in Bolt mode, and a compared pair whose sides differ in seed, options, build, node or card is void. `tools/proof/node_table` plans a proof row with the committed G1 table of its node's processor class, as the service plans on that node. `tools/proof/writers` writes PNG8, PNG16, TIFF16 and JPEG from a finished Large-image result's own planes and reads each file's bits per sample back from the file. `tools/proof/metrics` gains a measure command for the halo tools' interpreter.
