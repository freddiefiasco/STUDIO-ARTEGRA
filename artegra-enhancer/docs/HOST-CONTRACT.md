# Standalone host contract

- `host.app` owns one local service and all descendants through a Windows Job object. Closing or losing the host ends its owned child processes.
- The host writes a random per-run token file, supplies its PID to the service, then validates the service PID and loopback port from the handshake. Only ports 18950–18969 are accepted.
- QML receives `hostEndpoint` and `hostToken`. It never scans legacy endpoints. JSON requests use a Bearer header; image requests use the same token in their local URL because QML Image cannot attach headers. Token query values are redacted from logs.
- App settings are stored under the standalone organisation/application namespace. No other application's preferences are consulted. The enhancement tab's remembered choices are kept in `<state>/preferences.ini` (QML receives its file URL as `cuPrefsLocation`); an installed copy moves any that earlier copies kept in the registry into it once.
- While Settings or About is up, or setup covers the window, the workspace is hidden, so none of its keys, shortcuts, drops or focus can act behind the page.
- A second launch signals the first window through a local socket.
- The host owns the frame, folder setup and close handling. Imported components retain the image queue, viewer, controls and activity presentation.
- Demo and smoke modes use a fake engine and separate state. They never imply GPU image validation.
- While the window is open the host keeps a run record, `<state>/run/host.json`: its own process and the desktop launcher that started it, each as PID, creation time and executable path. It is removed on a normal exit.
- The single-instance connection accepts `activate` (bring the window forward) and `quit` (stop and close without a prompt; setup pauses safely and unfinished images resume on the next start).
- `ArtegraEnhancer.exe --quit-running [--state <root>] [--timeout <s>]` sends `quit` and waits for the recorded processes. Only if they do not end does it end the ones whose PID, creation time and path still match; it never looks processes up by name. Exit code 0: nothing of the app is left; 2: something could not be closed.
- `ArtegraEnhancer.exe --uninstall-cleanup [--remove-files] [--remove-settings] [--measure --out <file>] [--state <root>]` removes only app-managed files (see INSTALL.md). Both options read the app's records once, before either runs. `--remove-files` removes the manifest's model files and, in the managed engine folder, only setup's own entries by exact name; in its ComfyUI folder only files that match `runtime/source-manifest.json` byte for byte, plus `.pyc` files. Anything else there is kept and logged, and setup's two records stay while anything else does. `--measure` counts exactly what `--remove-files` removes. `--remove-settings` removes only the entries the app itself creates in a state folder, by exact name; anything else is kept and logged. Every output folder the app's records name (folders.json, settings.json, config.json, each job record) is kept by both options and never entered, and an app or engine folder holding one, or holding a file named like a result (`<name>_cu<N>x…`), is kept whole. Images are never in scope.
- Check for updates: one GET to `https://api.github.com/repos/freddiefiasco/STUDIO-ARTEGRA/releases?per_page=50` with the User-Agent `ArtegraEnhancer/<version>`, only when the person clicks. The newest non-draft `artegra-enhancer-v*` release, pre-releases included, is compared with the running version. Any failure, including an HTTP protocol error from a proxy or a cut-off answer, ends the check with the plain failure message.
- Redux is the API mode `standard`; Bolt is `fast`. `/api/controls` gives the names people read.
